📚 Technical-Document RAG Chatbot

Query technical PDFs and PowerPoint decks with an LLM — and get back not just text, but the images and tables from the source pages too, with source attribution for explainable results.

Self-hosted Runs 100% offline Tables & figures preserved Pluggable LLM Embeddable widget

👉 This page describes the tool's features. The chat bubble in the bottom-right corner is the live embeddable widget — ask it a question about the indexed documents. It talks to the RAG backend on a different origin, proving the cross-origin embed works like a real third-party site.

Why it's different

Most RAG chatbots embed text only, so during ingestion the images (diagrams, formulas) and tables (specs, parameters) in a technical document are discarded — even a correct text answer loses the artifact that carries the value. This tool keeps them: it extracts and stores tables and images keyed by document + page/slide, embeds table content as its own searchable unit, and at query time reconstructs and renders those assets inline next to the answer — scoped to the pages the answer actually cited.

Signature differentiators

Tables & figures survive ingestion

The core value of a technical document is preserved and rendered inline, not thrown away during vectorization.

Table content is searchable

Each table is embedded as its own unit, so a query matching cell values retrieves that page — not just nearby prose.

Three answer engines

Claude (API), a fully-offline local Qwen SLM, or zero-cost extractive — hot-swappable from a GUI, with safe auto-fallback.

Grounded by design

Per-claim page citations, a data-backed low-confidence banner, and an "I don't know" refusal instead of confident hallucination.

One backend, two front-ends

A Streamlit app and a one-line embeddable widget share the exact same retrieval and answer core.

Self-hosted & configurable

All user-facing text and appearance are tunable from a web admin console with no redeploy; can run with no outbound network calls.

Try the widget

Ask the chat bubble (bottom-right) something from the indexed documents:

  • "What is ProSe discovery in 3GPP LTE systems?"
  • "What bandwidth do users need for ProSe discovery?"
  • "What is the current consumption in dormant mode?"
  • "Summarize the spectrum allocation."
  • "Tell me about medieval French poetry." (should refuse — not in the docs, and shows no stray sources)

Honest limitations

  • No authentication yet — the app and widget API are currently open; this is the top-priority roadmap item and must be addressed before any public or multi-user deployment.
  • Widget is text + citations only today — no streaming and no inline figures/tables in the embedded widget (the Streamlit app has all three).
  • No OCR — scanned/image-only PDFs aren't text-extracted.
  • Local Qwen is slow on CPU (~1–2 min/answer) and may omit inline citation markers — Claude is the choice when speed and strict citations matter.

How this widget was embedded

The entire integration is a single script tag:

<script src="http://localhost:8000/widget/widget.js"
        data-api="http://localhost:8000/api"></script>

Replace localhost:8000 with wherever the API is hosted. For a real cross-origin embed the API must be on a public HTTPS host with CORS configured.
